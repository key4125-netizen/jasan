## BOND-1 · 개별채권의 경제적 정의 (HTM / MTM / 통합)

| 축 | 내용 |
| --- | --- |
| 현재 앱 상태 | 사실상 HTM에 가깝다 — `채권`은 시세조회 대상이 아니고(`NON_TRADABLE_CATEGORIES`), Risk 대상에서 빠지며(`RISK_ELIGIBLE_CATEGORIES=['주식','ETF']`), MC에서 σ=0이다 |
| 장점 | HTM: 사용자가 이해하기 쉽고 데이터 요구가 적다(만기 · 쿠폰 · 매입가만으로 성립) / MTM: 주식과 같은 축에서 비교 가능 · 금리 위험이 드러난다 |
| 문제 | HTM: 금리 상승기에 "위험 0"으로 보인다(사실과 다른 인상) / MTM: 평가가격이 없으면 계산 자체가 불가 · 사용자가 "왜 채권이 손실?"로 혼란 |
| 필요 데이터 | HTM: 사용자 입력만(만기 · 쿠폰 · 주기 · 매입가) / MTM: 일별 평가가격 또는 평가수익률(채권시세정보 · 제4유형) |
| 구현 영향 | HTM: 현금흐름 계산기 신설(중간) / MTM: 평가 파이프라인 + 원천 라이선스(큼) |
| UX 영향 | HTM: 기존 화면 유지 / MTM: 평가손익 표시 신설 |
| MC 영향 | HTM: 기대수익률을 YTM으로 둘 근거가 생긴다 / MTM: σ · 상관이 필요 |
| Risk 영향 | HTM: 여전히 Risk 밖 / MTM: 금리 민감도 반영 |
| **권고(결정 아님)** | **HTM을 기본 표현으로, 금리 시나리오에서만 MTM 관점을 별도 표시**하는 축소형 통합. 데이터 요구와 사용자 이해의 균형점이며, 제4유형 라이선스 제약을 피할 수 있다 |

## BOND-2 · 채권을 Risk 진단 대상에 넣을 것인가

| 축 | 내용 |
| --- | --- |
| 현재 | 직접채권 제외 · 채권 ETF는 포함되지만 Benchmark가 없어 베타 없음 |
| 장점 | 포함 시 포트폴리오 전체 위험을 한 화면에서 볼 수 있다 |
| 문제 | 채권 위험을 "주식과 같은 지표(베타 · 변동성)"로 표현하면 의미가 왜곡된다 |
| 필요 데이터 | 직접채권: 듀레이션 또는 평가가격 시계열 / 채권 ETF: 이미 가격 있음 |
| 구현 영향 | `RISK_ELIGIBLE_CATEGORIES` 확대는 여러 화면에 파급 — 작지 않다 |
| UX 영향 | 위험 카드에 채권 항목이 등장 |
| MC 영향 | 없음(별개) |
| Risk 영향 | 포트폴리오 변동성 · 집중도 · 점수가 바뀐다 → 전후 측정 필수 |
| **선택지** | (가) 현행 유지 (나) **채권 ETF만 정식 편입**(가격이 이미 있음) (다) 직접채권까지 |

## BOND-3 · 채권 Risk 모델

| 후보 | 데이터 요구 | 정확성 | 구현 난이도 | 사용자 이해 | 데이터 확보 가능성 | Risk 결과 영향 |
| --- | --- | --- | --- | --- | --- | --- |
| R1 듀레이션 × 금리변화 | 수정듀레이션 + 금리 시계열 | 중 | 중 | 쉬움("금리 1% 오르면 약 N% 하락") | 듀레이션은 사용자 입력 또는 근사 | 금리 시나리오에 직접 반영 |
| R2 수정듀레이션(볼록성 포함) | R1 + 볼록성 | 중상 | 중상 | 어려움 | 낮음 | R1과 유사 |
| R3 스프레드 듀레이션 · 신용스프레드 | 등급별 스프레드 시계열 | 상 | 상 | 어려움 | 국내 스프레드 시계열 확보 미확인 | 회사채 위험 반영 |
| R4 채권지수 변동성 | 채권지수 일별 시계열 | 중상 | 중 | 중간 | **KRX 채권지수는 화면 공개 · 라이선스 필요** | 변동성 · MDD 산출 가능 |
| R5 개별 평가가격 수익률 | 종목별 일별 평가가격 | 상 | 상 | 중간 | 채권시세정보(제4유형) 또는 평가사 유료 | 가장 정확하나 제약 큼 |
| **권고(결정 아님)** | 채권 ETF = **R4 또는 ETF 자체 시계열**, 직접채권 = **R1**(듀레이션 근사 시 그 사실을 화면에 명시) | | | | | |

## BOND-4 · MC σ=0 유지 여부

| 축 | 내용 |
| --- | --- |
| 현재 | 채권 · 현금 σ=0(§7 · BOND-DEF-03). "데이터 없음"과 "변동성 0"이 사실상 같게 처리돼 있다 |
| 장점 | 단순 · 기존 결과 안정 |
| 문제 | **경제적으로 틀렸다.** 채권도 금리에 따라 변동한다. PM 지시도 "데이터 없음 = 변동성 0"을 금지한다 |
| 필요 데이터 | 채권 자산군 σ · 상관 — **CMA 세트에 이미 채권 자산군이 있다**(추가 수집 불필요) 또는 채권지수 실측 |
| 구현 영향 | MC 입력 매핑만 바꾸면 되지만 **결과가 바뀐다** |
| UX 영향 | 예측 구간이 넓어진다(더 정직) |
| MC 영향 | P10/P50/P90 변화 → 동일 seed 전후 측정 필수 |
| Risk 영향 | 없음 |
| **선택지** | (가) 유지 (나) **CMA 채권 σ · 상관 사용**(추가 데이터 없이 가능) (다) 채권지수 실측 σ(라이선스 선행) |

## BOND-5 · 포트폴리오 베타 집계 정책 (대장 M-5)

| 축 | 내용 |
| --- | --- |
| 현재 | 베타를 못 구하는 종목이 하나라도 있으면 포트폴리오 베타 = null. 채권 ETF 1개만 있어도 비게 된다 |
| 장점 | 정직하다(없는 값을 만들지 않는다) |
| 문제 | 실사용에서 거의 항상 비어 있어 지표가 죽는다 |
| 필요 데이터 | 없음(정책 문제) |
| 구현 영향 | 집계 규칙 + 표시 문구 |
| UX 영향 | "주식 부분만 집계했고 채권 N%는 제외" 같은 명시가 필요 |
| MC 영향 | 없음 |
| Risk 영향 | 포트폴리오 베타 · 시장위험 요인 점수 |
| **선택지** | (가) 현행 유지 (나) **베타 산출 가능한 부분만 집계 + 제외 비중을 함께 표시** |

## BOND-6 · KRX 채권지수 데이터 이용

| 축 | 내용 |
| --- | --- |
| 현재 | 화면에서 일별 시계열이 보이는 것은 확인. **데이터 이용은 "지수 정보상품 신청" 대상**임이 KRX 문구로 확인됨 |
