## 1. BOND-1 — 경제적 정의

**[FACT]** 시장가격 원천(채권시세정보)은 공공누리 제4유형(변경금지·상업이용금지)이라 **상시 저장·배포가 불가**하다. 반면 사용자가 입력하는 매입정보와 공식 발행조건(만기·쿠폰·주기)은 제약 없이 쓸 수 있다.

**[SOLUTION]** 수익을 **두 계층으로 나눈다.**

| 계층 | 언제나 계산 가능 | 내용 |
| --- | --- | --- |
| **확정 계층**(기본 표시) | ✔ 시장가격 없어도 가능 | 매입금액 · 수령/예정 쿠폰 · 만기 상환금액 · **매입 시 YTM**(만기보유 가정 수익률) · 남은 기간 · 다음 이자일 |
| **평가 계층**(보조 표시) | 시장가격이 있는 날만 | 현재 평가금액 · 평가손익 · Current Yield · 현재가 기준 YTM |

- ①의 해결: 기본 화면은 확정 계층만으로 구성한다. 평가 계층은 **그 날 시세를 받았을 때만** 나타나고, 없으면 "오늘 시장가격 없음"이라고 쓴다(빈칸을 0으로 채우지 않는다).
- ②: 시장가격이 없어도 **매입금액 · 실현 쿠폰 · 매입 시 YTM · 만기 예상 상환액 · 만기까지 남은 기간**은 전부 계산된다.
- ③: **YTM = 만기까지 보유했을 때의 연환산 예상 수익률**, **보유성과 = 지금까지 실제로 받은 쿠폰 + (평가/매도)차익**. 두 값을 같은 줄에 나란히 두지 않고 라벨을 분리한다.
- ④: 쿠폰수익(실현·확정)과 평가손익(미실현·시장)은 **다른 블록**에 표시한다. 합산 표시는 "총수익(쿠폰+평가)"으로 별도 라벨을 달 때만 한다.
- ⑤: 만기 예정 채권은 "만기 D-일 · 예상 상환액", 중도매도 채권은 "매도 완료 · 실현손익"으로 **상태가 다른 카드**를 쓴다.

**[POLICY]** BOND-1 = C안(통합형, 기본=확정 계층). 회계기준의 HTM/MTM 분류가 아니라 **앱의 투자관리 표시정책**임을 문구로 못박는다.

## 2. BOND-2 — Risk 편입

**[FACT]** `RISK_ELIGIBLE_CATEGORIES = ['주식','ETF']`(js/09) — 직접채권은 위험 진단에서 제외된다. 위험점수는 6요인 가중합(집중도0.25 · 변동성0.20 · 손실0.20 · 시장0.15 · 상관0.10 · 기술0.10)이다.

**[SOLUTION]** 기존 점수 구조를 **건드리지 않고** 층을 하나 더 얹는다.

```
[주식 위험]   기존 그대로 — 베타 · 변동성 · VaR · CVaR · 위험점수(6요인)
[채권 위험]   신설 — 평균 듀레이션 · 금리 ±100bp 영향 · 신용등급 분포 · 통화 노출
[포트폴리오]  두 위험을 나란히 + 주식/채권 비중 + 집중도
```

- 기존 위험점수 계산식 · 가중치 · 대상 자산은 **변경 없음** → 기존 사용자 수치가 흔들리지 않는다.
- 채권 위험은 **별도 카드**로 제공한다. 점수화(0~100)는 하지 않는다 — 주식 점수와 섞이면 의미가 무너진다.

**[POLICY]** BOND-2 = C안. **[CONSTRAINT]** 채권 카드가 생기려면 직접채권이 진단 파이프라인에 들어와야 하므로 `RISK_ELIGIBLE_CATEGORIES` 확대가 필요하다(SoT 변경안 §7-1).

## 3. BOND-3 — 직접채권 Risk 모델

**[SOLUTION]** 질문 ①~⑧에 대한 답을 모델로 확정한다.

| 질문 | 해결 |
| --- | --- |
| ① 수정듀레이션을 입력값만으로 구할 수 있나 | **가능하다.** 만기 · 표면이율 · 지급주기 · (YTM 대용으로) 매입 시 YTM이면 Macaulay → Modified 계산이 성립한다. 전부 공식 API + 사용자 입력에서 나온다 |
| ② 지급주기가 다르면 | 주기(m)를 그대로 현금흐름 시점에 반영하고 D_mod = D_mac / (1 + y/m) |
| ③ 할인채 · 복리채 | 중간 현금흐름이 없으므로 **D_mac = 잔존만기**(정의상 정확). 오히려 이표채보다 단순하다 |
| ④ 잔존만기가 짧아지면 | 듀레이션이 함께 줄어 민감도가 자동으로 작아진다(모형이 스스로 처리) |
| ⑤ 금리 shock 폭 | **±100bp를 기본**으로 하고 ±50/±200을 보조로 표시(정책 고정값 · 난수 없음) |
| ⑥ 국내 vs 외화 | 금리민감도 계산은 동일. **다른 것은 어느 나라 금리를 흔드느냐**와 환노출이다 → 통화별로 분리 표시 |
| ⑦ 신용 | 스프레드 시계열이 없으므로 **수치화하지 않는다.** 대신 **신용등급 · 채권순위 · 발행인 유형**을 위험정보로 표시한다(사실 그대로) |
| ⑧ 시장가격 없을 때 | **금리민감도는 계산된다**(가격이 아니라 현금흐름 구조에서 나오기 때문). 평가손익만 계산 불가 |

**최종 Risk output(직접채권)**: 잔존만기 · 수정듀레이션(모형값) · 금리 ±100bp 영향률 · 신용등급 · 통화 · (가능하면) 평가손익.
**fallback 순서**: 듀레이션 모형 → (채권지수 대용, 라이선스 확보 시) → 계산 불가 표시. **σ=0으로 떨어뜨리지 않는다.**

## 4. BOND-4 — MC 해결 **(핵심 해결)**

**[FACT]** 현재 BOND는 `app-asset-class-map.json`에서 unmapped이고 `js/16:114`가 riskFree(σ=0)로 처리한다.
**[FACT]** AllianzGI(PRIMARY) 세트에는 **한국 채권 자산군이 없다**(US/Euro/Global/Asian/EM 채권만 있다).
**[FACT · 해결의 열쇠]** 그런데 같은 CMA 세트의 **J.P. Morgan LTCMA 2026 KRW**(이미 저장소에 있음 · role=BENCHMARK · 통화 KRW · 62개 자산군)에는 다음이 있다.

| 자산군 | 기대수익률 | 변동성 |
| --- | ---: | ---: |
| **Korean Government Bonds** | 3.0% | 5.36% |
| **Korean Corporate Bonds** | 3.5% | 2.54% |
| Korean Cash | 2.2% | 0.48% |
| U.S. Intermediate Treasuries (비헤지) | 2.0% | 11.14% |
| U.S. Intermediate Treasuries **hedged** | 3.2% | 3.45% |
| U.S. High Yield Bonds / hedged | — | — |
| World Government Bonds / hedged | — | — |

→ **국내채권 CMA가 없다는 문제는 실제로는 없다.** 원화 기준 공식 장기가정이 이미 확보돼 있고, **헤지/비헤지 쌍**까지 있어 외화채권 FX·헤지 처리의 근거도 된다.

**[SOLUTION]** 매핑안

| 보유 유형 | 연결 대상(JPM KRW) | 근거 |
| --- | --- | --- |
| 국내 국채 · 지방채 · 특수채 | Korean Government Bonds | 발행인 유형 |
| 국내 회사채 · 금융채 | Korean Corporate Bonds | 발행인 유형 |
| 미국 국채(비헤지) | U.S. Intermediate/Long Treasuries | 통화 · 헤지 여부 |
| 미국 국채(헤지) | 같은 자산군의 **hedged** 행 | 헤지 사실이 A등급으로 확인된 경우만 |
| 분류 불가 | **연결하지 않는다** → MC에서 그 자산은 "가정 없음"으로 제외하고 사유를 표시 | 임의 분류 금지 |

- ② 신용등급: 공공 API의 `채권순위` · `발행인명` · `금리구분`은 받을 수 있으나 **신용등급 자체는 확인되지 않았다** → 국채/회사채 구분은 발행인 유형으로 하고, 등급별 세분(IG/HY)은 **사용자 입력이 있을 때만** 한다.
- ④⑤ **fallback은 σ=0이 아니다.** 연결 근거가 없으면 **그 자산을 MC에서 제외하고 "장기 가정 없음"으로 안내**한다(기존 "가정 없으면 실행 안 함" 정책과 같은 방식).
- ⑦ 직접채권과 채권 ETF: 기초가 같으면 같은 자산군을 쓴다(예: 국고채 ETF ↔ Korean Government Bonds). 다만 ETF는 자체 가격 시계열이 있으므로 Risk는 다른 경로다.
- ⑨ 헤지 미확인: **헤지 자산군을 쓰지 않는다**(비헤지로도 단정하지 않는다) → 연결 보류.

**[CONSTRAINT · POLICY]** JPM 세트는 현재 `role=BENCHMARK · numberKind=BENCHMARK_REFERENCE`다. 이를 채권 μ/σ의 **근거로 승격**하려면 §37 CMA 정책의 역할 정의를 바꿔야 한다(SoT 변경안 §7-3). 데이터는 이미 있고 필요한 것은 승인이다.

## 5. BOND-5 — Portfolio Beta

**[FACT]** §44 제10조: 베타를 못 구하는 종목이 하나라도 있으면 포트폴리오 베타 null.
**[SOLUTION]** 베타의 의미를 지키면서 값을 되살린다.

```
주식 베타      1.12   (주식 보유의 88%를 반영)
베타 커버리지  88%    (베타를 못 구한 주식 12%는 제외)
채권 비중      22%    (베타 대상 아님 — 별도 채권 위험 참조)
```

- **채권은 주식 베타 집계 대상이 아니다**(0으로 넣지 않는다 · 제외한다).
- 주식 중 베타를 못 구한 종목이 있으면 **그 비중을 커버리지로 표기**한다 → "전부 아니면 무"의 취지(모르면 모른다고 말한다)를 표기로 대체한다.
- 커버리지가 낮으면(예: 50% 미만) 값을 숨기고 사유를 표시한다.

**[POLICY]** BOND-5 = C안 + 커버리지 표기. 제10조 개정 필요(SoT 변경안 §7-2). 대장 M-5와 같은 결정이다.

## 6. BOND-6 — 라이선스

**[FACT]** 채권기본정보 · 권리일정정보 · 발행정보 = 공공누리 **제2유형**(출처표시 + 상업적 이용금지) / 채권시세정보 = **제4유형**(+변경금지) / KRX 지수 = 정보상품 신청 대상.

**[SOLUTION]** 기능을 데이터 등급별로 나눈다 — 라이선스 때문에 기능 전체를 포기하지 않는다.

| 기능 | 필요한 데이터 | 등급 | 가능 여부 |
| --- | --- | --- | --- |
| ISIN 자동조회 · 발행조건 채우기 | 채권기본정보 | 제2유형 | **가능** |
| 이자지급일 채우기 | 권리일정정보 | 제2유형 | **가능** |
| 현금흐름 · 매입 시 YTM · 만기 예상 | 위 + 사용자 입력 | — | **가능**(외부 시세 불필요) |
| 금리민감도(듀레이션) | 위와 동일 | — | **가능** |
| 평가금액 · 평가손익 · Current Yield | 채권시세정보 | 제4유형 | **조건부** — 사용자 브라우저가 조회해 **그 화면에서만** 쓰고 저장·배포하지 않는다 |
| 채권 변동성 실측 · 지수 비교 | 채권지수 | 정보상품 | **현재 불가** → CMA(JPM KRW)로 대체 |

**[CONSTRAINT]** "변경금지"가 파생 계산에 어디까지 미치는지는 문구만으로 단정할 수 없다 → **[LICENSE REVIEW]** 로 남기고, 그 사이에는 "저장하지 않고 화면에서만"이라는 보수적 운영을 택한다. 상시 필요해지면 KRX Data Marketplace 문의가 정식 해소 경로다.

## 7. D-5 — KOSPI200 PR/TR

**[FACT]** 정의는 이미 A등급으로 확정(KRX 공식). 일별 시계열만 없다.

**[SOLUTION · 중요한 부정 결과]** "ETF 가격을 지수 proxy로 쓰자"는 안을 실제로 따져 본 결과 **이 경우엔 의미가 없다.**
- 069500 · 102110 · 278530의 베타를 구하려는 것인데, proxy로 쓸 후보가 **바로 그 ETF들 자신**이다. 자기 자신에 대한 베타는 정의상 1이 되어 **정보가 0**이다.
- 다른 종목이 KOSPI200을 기준으로 삼는 경우가 현재 원장에 **없다**.
→ 따라서 proxy 도입은 이 문제를 풀지 못한다(형식적 대안이므로 채택하지 않는다).

**[SOLUTION] 실효 경로는 둘뿐이다.**
1. **사용자 인증키 직접조회** — 공공데이터 지수시세정보는 **CORS 허용이 실측 확인**돼 브라우저에서 바로 호출된다(프록시 불필요). 재배포도 없다. 필요한 것은 사용자 무료 키 1개 + 키 입력 UI(신규 기능 → PM 승인).
2. **KRX 지수 정보상품 신청**(유료 가능성).
그래도 안 되면 정의만 확정한 채 **원천 없음(현행 상태)** 을 유지한다 — 이는 이미 정직하게 표시되고 있다(Benchmark RESOLVED + 가격원천 UNAVAILABLE).

**[POLICY]** D-5 = (가)사용자 키 / (나)라이선스 / (다)현행 유지 중 선택. **proxy는 권고하지 않는다.**

## 9. B-1 — KIS Worker 보안 **(코드에서 결함 특정)**

**[FACT]** 저장소의 `cloudflare-worker-kis-proxy.js`(301줄)에서 두 가지 실제 결함을 확인했다.
1. **CORS 전면 개방** — `'Access-Control-Allow-Origin': '*'`(43행). 누구나 이 Worker를 호출할 수 있다.
2. **비밀키 검사 fail-open** — `if (env.CLIENT_SHARED_SECRET && request.headers.get('X-App-Secret') !== ...)`(272행). 환경변수를 등록하지 않으면 **검사가 통째로 건너뛰어진다.**
또한 KV는 토큰·응답 캐시에만 쓰이고 **요청 수 제한이 없다**.

**[SOLUTION]** 수정안(구현은 승인 후)

| 항목 | 현재 | 수정안 |
| --- | --- | --- |
| CORS | `*` | 허용 목록만: `https://key4125-netizen.github.io`, 개발용 `http://localhost:8644`. 목록에 있을 때만 그 Origin을 반사하고 `Vary: Origin` 추가 |
| 인증 | 변수 없으면 무검사 | **fail-closed**: `CLIENT_SHARED_SECRET`이 없으면 503으로 거절(서비스하지 않음) |
| 요청 제한 | 없음 | KV 카운터로 IP·일 300건 / 분 30건 초과 시 429 |
| 오류 노출 | 상류 응답 전달 가능 | 상태코드만 반환하고 상류 본문·헤더는 전달하지 않음 |
| 비밀값 | KIS_APP_KEY/SECRET는 Worker 환경변수(정상) | 회전 후 재배포 |

**[CONSTRAINT]** 공개 PWA에 들어가는 `X-App-Secret`은 **본질적으로 공개값**이다 → 이것만으로 접근통제가 되지 않는다. 실질 방어선은 **Origin 허용목록 + 요청 제한**이다. 이 사실을 문서에 명시한다.

**[EXTERNAL ACTION]** Cloudflare 대시보드 작업 순서
1. Workers & Pages → 해당 Worker → Settings → Variables: `KIS_APP_KEY` · `KIS_APP_SECRET` 새 값으로 교체(KIS 포털에서 재발급), `CLIENT_SHARED_SECRET` 새 임의값 등록
2. 같은 화면에서 KV 네임스페이스 바인딩 확인(`KIS_KV`)
3. 수정된 Worker 코드 배포
4. 프론트 설정의 공유 비밀값 교체(앱 쪽 상수)
5. 확인: 허용 목록 밖 Origin에서 호출 → 차단 / 비밀값 없이 호출 → 거절 / 과다 호출 → 429

## 12. SoT 변경안

### §7-1 · Risk 대상 확대 (BOND-2)
- **[CURRENT]** 위험 진단 대상 = 주식 · ETF (`RISK_ELIGIBLE_CATEGORIES`)
- **[PROBLEM]** 직접채권이 통째로 빠져 사용자는 채권의 금리위험을 전혀 볼 수 없다
- **[PROPOSED]** 채권을 진단 대상에 포함하되 **주식 위험점수 계산에는 넣지 않고** 별도 채권 위험 지표로 산출한다
- **[WHY]** 기존 점수의 의미·수치를 보존하면서 빠진 위험을 복원한다
- **[IMPACT]** 위험 화면에 채권 카드 추가 · 기존 점수 무변경
- **[REGRESSION]** risk fixture 전후 동일(주식 지표) · 채권 카드 신규 검증
- **[ROLLBACK]** 카테고리 목록 원복

### §7-2 · 포트폴리오 베타 (BOND-5 · §44 제10조)
- **[CURRENT]** 하나라도 베타가 없으면 null
- **[PROBLEM]** 채권 1종목만 있어도 항상 비어 지표가 죽는다
- **[PROPOSED]** 주식만 대상으로 집계하고 **커버리지(%)** 를 함께 표시 · 커버리지 하한 미만이면 숨김
- **[WHY]** "모르면 모른다"는 원칙을 값 숨김이 아니라 **범위 명시**로 지킨다
- **[IMPACT]** 포트폴리오 베타가 다시 표시된다(현재 fixture 기준 null → 값)
- **[REGRESSION]** risk 회귀 전후 측정 필수
- **[ROLLBACK]** 규칙 원복

### §7-3 · MC 채권 자산군 (BOND-4 · §37 · §7 σ=0)
- **[CURRENT]** 채권 · 현금 σ = 0 · BOND unmapped · JPM 세트는 상관 Benchmark 전용
- **[PROBLEM]** "데이터 없음"이 아니라 **매핑 부재**인데 결과는 "위험 0"으로 표시된다
- **[PROPOSED]** JPM LTCMA KRW의 Korean Government/Corporate Bonds 등을 **채권 μ·σ 근거로 사용**하고, 연결 근거가 없는 채권은 MC에서 제외(가정 없음)
- **[WHY]** 원화 기준 공식 장기가정이 이미 있고, σ=0보다 정직하다
- **[IMPACT]** MC 분포 변화(채권 비중에 비례) · 동일 seed 전후 측정 필수
- **[REGRESSION]** mc invariant(기존 49건 주식 결과) 유지 확인 + 채권 포함 시 전후 비교
- **[ROLLBACK]** 매핑 제거 시 즉시 원복(데이터 파일만 변경)

### §7-4 · HOME_COMMON 규칙 v2 (D-11)
- **[CURRENT]** 증권 종류가 "보통주"로 표기된 경우만
- **[PROBLEM]** 같은 발행인의 의결권만 다른 지분증권(Class C)이 불필요하게 보류된다

- **[IMPACT]** GOOG 1건 변경(측정 완료: RESOLVED 33→34)

- **[ROLLBACK]** 규칙 v1 복귀
