## 1. 전체 구조

```
사용자 → [ISIN 입력] → [공식 채권정보 조회] → [조회 결과 확인 화면] → 사용자 확인
      → [Bond Ledger 등록: Official Terms]
      → [보유정보 입력: User Holding]
      → [Cash Flow / Accrual Engine] → [Yield Engine]
      → [Bond Risk Engine] → [Portfolio Risk] → [Monte Carlo]
```

### 1-1. 네 계층을 절대 섞지 않는다 **[DESIGN]**

| 계층 | 내용 | 출처 | 누가 바꾸나 |
| --- | --- | --- | --- |
| **A. Official Instrument Fact** | 만기 · 쿠폰 · 이자유형 · 지급주기 · 통화 · 발행일 · 잔액 | 공공 API(채권기본정보 등) | 자동 갱신 가능(§7) |
| **B. User Holding Fact** | 매입일 · 수량/액면 · 매입단가 · 매입금액 · 계좌 · 과세구분 | **사용자만** | **자동 경로 접근 금지** |
| **C. Market Fact** | 기준일 · 현재가격 · 현재수익률 | 시세 API(제4유형) | 조회 시점마다 새로 받음 · 저장 안 함 |
| **D. Derived** | 경과이자 · YTM · 보유기간수익률 · 평가손익 · 듀레이션 · Risk 지표 | 계산 | 저장하지 않고 매번 계산(또는 캐시 명시) |

**불변 규칙**: A가 갱신돼도 B는 그대로다. D는 A·B·C에서 파생될 뿐 스스로 값을 갖지 않는다.

## 2. Bond Ledger 스키마 **[DESIGN]**

기존 자산(js/01 `makeAsset`)은 `ticker · quantity · buyPrice · currentPrice` 중심이라 채권의 액면 · 쿠폰 · 만기를 담을 수 없다. **기존 asset 구조를 바꾸지 않고**, 채권만 별도 레코드를 갖고 자산과 1:1로 연결하는 방식을 제안한다(기존 데이터 무변경 · 마이그레이션 없음).

```
bondPositions: [
  {
    id,                      // 자체 id
    assetId,                 // 기존 state.assets 항목과 연결(1:1) — 기존 구조 무변경

    identity: {              // A. Official Instrument Fact
      isin, instrumentName, issuer, currency,
      bondType,              // 국채 · 지방채 · 특수채 · 회사채 · 금융채 (원천 값 그대로)
      seniority              // 채권순위
    },
    terms: {
      issueDate, maturityDate,
      faceValue,             // 액면가(1좌/1매 기준)
      issuePrice,            // 발행가 — 매입가와 다르다
      couponRate,            // 표면이율(연 %)
      couponType,            // 이표채 · 할인채 · 복리채 (원천 값)
      rateType,              // 고정 · 변동
      paymentFrequency,      // 연 지급 횟수
      paymentDates: [],      // 권리일정정보에서 오면 채움 · 없으면 빈 배열
      outstandingAmount
    },
    source: {                // A 계층 메타데이터(최소한만)
      provider: 'data.go.kr/채권기본정보',
      sourceDate,            // 원천 기준일자
      retrievedAt,
      evidenceGrade: 'A',
      lastVerifiedAt
    },
    userOverride: {          // 사용자가 공식 값을 고친 경우 — 원본을 덮어쓰지 않는다
      // 예: { couponRate: 3.25, reason: '...', at: '...' }
    },

    holding: {               // B. User Holding Fact — 자동 경로 접근 금지
      account, purchaseDate,
      faceAmount,            // 보유 액면 총액(또는 수량)
      purchaseUnitPrice,     // 액면 10,000 기준 단가 등 — 단위는 아래 3장
      purchaseAmount,        // 실제 지급액
      accruedInterestAtPurchase,
      taxType
    }
  }
]
```

**메타데이터는 A 계층에만** 둔다(B·C·D에는 붙이지 않는다 — 과도한 메타데이터 금지).
저장 키는 기존과 분리한 새 키(예: `sam_bond_positions_v1`)를 쓴다 **[DESIGN]** — 기존 `sam_assets_v5`를 건드리지 않는다.

## 3. 가격 의미(Price Semantics) **[DESIGN]**

채권 가격 혼동은 사고로 이어진다. 내부 표현을 하나로 못박는다.

| 개념 | 정의 | 내부 표현 |
| --- | --- | --- |
| faceValue | 액면가(상환 기준 금액) | 금액(원/통화) |
| issuePrice | 발행 시 가격 | **액면 100 기준 단가** |
| purchaseUnitPrice | 사용자가 산 단가 | **액면 100 기준 단가**(입력 UI에서 명시) |
| purchaseAmount | 실제 지급 금액 | 금액 |
| currentPrice | 현재 시장 단가 | **액면 100 기준 단가** |
| marketValue | 평가금액 | 금액 = faceAmount × currentPrice / 100 |

**규칙**: 단가는 전부 "액면 100 기준", 금액은 전부 통화 금액. 저장할 때 어느 쪽인지 필드명으로 구분하고, 화면에는 단위를 항상 함께 표시한다.

## 4. ISIN 자동조회 UX **[DESIGN]** (모바일 375px 기준 · 기존 자산 입력 화면 재사용)

```
[자산 추가] → 종류 '채권' 선택
  ├ (선택) ISIN 입력 → [조회]
  │    ├ FOUND               → 조회 결과 카드 표시 → [이 정보로 채우기]
  │    ├ MULTIPLE_MATCH      → 후보 목록(최대 N개) → 사용자가 선택
  │    ├ NOT_FOUND           → "공식 정보를 찾지 못했습니다" → 직접 입력으로 진행
  │    ├ SOURCE_UNAVAILABLE  → "지금 조회할 수 없습니다"(원천 장애/키 없음) → 직접 입력
  │    ├ SOURCE_DATA_INCOMPLETE → 일부만 채우고 **빈 칸은 비워 둔다**(0으로 채우지 않음)
  │    └ LICENSE_RESTRICTED  → 해당 항목은 표시만 하고 저장하지 않는다
  └ 보유정보 입력(필수): 매입일 · 보유액면 · 매입단가 · 계좌
```

- 자동으로 채운 항목에는 **출처 · 기준일 배지**를 붙인다(예: "공공데이터 채권기본정보 · 2026-09-19 기준").
- 사용자가 자동 입력 값을 고치면 **원본은 `source`에 남기고 `userOverride`에 기록**한다. 화면에는 "사용자 수정됨"을 표시한다.
- 최소 입력(ISIN 없이도 등록 가능): 채권명 · 발행기관 · 매입일 · 보유액면 · 매입단가 · 표면이율 · 지급주기 · 만기일.
- 새 화면을 따로 만들지 않고 **기존 자산 추가 폼에 '채권' 전용 섹션**을 확장한다.

## 5. Cash Flow / Accrual Engine **[DESIGN]**

| 흐름 | 시점 | 금액 |
| --- | --- | --- |
| 매입 | purchaseDate | −(purchaseAmount + accruedInterestAtPurchase) |
| 쿠폰 | paymentDates(또는 지급주기로 생성) | faceAmount × couponRate / 지급횟수 |
| 만기 상환 | maturityDate | faceAmount(할인채·복리채는 상환금액 규칙이 다르다) |
| 중도매도 | 사용자 입력 | 매도금액 + 경과이자 |

- **지급일**: 권리일정정보에서 받으면 그대로 쓰고, 없으면 만기일 기준 역산으로 **생성했다는 사실을 표시**한다(생성값과 공식값을 구분).
- **경과이자**: 직전 지급일~평가일 경과분. 일수 계산 규칙(관행)은 **[PM]** 결정 항목(예: 실제일수/365).
- **쿠폰유형별 차이**: 이표채(정기 지급) · 할인채(지급 없음, 액면 상환) · 복리채(만기 일시). `couponType`에 따라 흐름 자체가 달라진다.
- **입력 부족 시**: 만기일 또는 표면이율이 없으면 현금흐름을 만들지 않는다 → 화면에 "만기일이 없어 계산할 수 없습니다"를 표시하고 **추정하지 않는다**.

### 채권 ETF는 별도
채권 ETF는 현금흐름 모델을 쓰지 않는다. 기존 ETF와 같이 **시장가격 시계열**로 다룬다(분배금은 기존 ETF 처리 방식 그대로).

## 6. Yield Engine **[DESIGN]**

| 지표 | 정의 | 필요한 입력 | 없을 때 |
| --- | --- | --- | --- |
| Coupon Yield(표면이율) | couponRate | 표면이율 | 계산 불가 |
| Current Yield | 연 쿠폰 ÷ 현재가격 | 표면이율 · 현재가격 | 현재가격 없으면 **계산 불가**(0 금지) |
| **YTM** | 현금흐름 현가 = 현재가격이 되는 할인율 | 지급일정 · 현재가격 · 만기 | 어느 하나 없으면 계산 불가 |
| 매입 시 YTM | 위와 같되 매입가 · 매입일 기준 | 매입단가 · 매입일 · 일정 | 〃 |
| Holding Period Return | (수령 쿠폰 + 평가 or 매도차익) ÷ 매입금액 | 매입정보 + (현재가 or 매도가) | 평가 없으면 **쿠폰 수령분만** 표시(부분 표시 · 명시) |
| 평가손익 | marketValue − purchaseAmount | 현재가격 | 계산 불가 |
| 이자수익(실현) | 수령한 쿠폰 합 | 지급일정 · 보유기간 | 일정 없으면 불가 |
| 만기상환손익 | 상환금액 − 매입금액 | 만기 · 액면 · 매입 | 〃 |

**기본 표시 · 보조 표시** **[PM 결정 필요]**
- 권고: 기본 = **매입 시 YTM(만기까지 보유 가정 수익률)** + 실현 쿠폰, 보조 = 현재가격이 있을 때만 **평가손익 · Current Yield**.
- 이유: 개인 투자자의 직접보유 채권은 만기 보유가 일반적이고, 시장가격 원천이 제4유형이라 상시 확보를 전제할 수 없다.

## 7. Bond Risk Engine **[DESIGN]**

### 직접채권
1순위 **듀레이션 × 금리변동**: ΔP/P ≈ −D_mod × Δy.
- D_mod를 사용자 입력으로 받거나, 없으면 **만기 · 쿠폰 · 지급주기로 계산(Macaulay → Modified)** 한다. 계산으로 얻은 값은 화면에 **"모형값"** 으로 표시한다.
- 금리 충격 시나리오(예: ±100bp)는 **정책으로 고정**하고 임의 난수를 쓰지 않는다 **[PM]**.
- 신용은 등급별 스프레드 시계열이 없으면 **반영하지 않는다**(반영한 척하지 않는다).

2순위 채권지수 대용(BOND-6 라이선스 확보 시) · 3순위 개별 평가가격(유료).
**fallback 순서**: 듀레이션 모형 → (지수 대용) → **계산 불가 표시**. σ=0으로 떨어뜨리지 않는다.

### 채권 ETF
기존 ETF 경로 그대로 **자체 가격 시계열**로 변동성 · MDD를 구한다. Benchmark(채권지수)가 없으면 베타만 비운다 — 지금 동작과 같다.

### 절대 금지
주식 베타를 채권에 적용하지 않는다. "데이터가 없으니 위험 0"으로 쓰지 않는다.

## 8. Portfolio Risk 연계 **[DESIGN]** (BOND-5)

- 주식 베타 집계에서 **채권은 제외**하고, 제외된 비중을 화면에 명시한다.
- 채권 위험은 **별도 지표**(금리 민감도 · 평균 듀레이션 · 만기 분포)로 보여 준다.
- 기존 위험점수(6요인: 집중도 0.25 · 변동성 0.20 · 손실 0.20 · 시장민감도 0.15 · 상관 0.10 · 기술 0.10)에 **새 요인을 임의로 추가하지 않는다** — 점수 구조 변경은 **[PM]**.

## 9. Monte Carlo 연계 **[DESIGN]** (BOND-4)

**[FACT]** 현재: `data/cma/app-asset-class-map.json`이 BOND를 `unmapped`로 두고("채권은 기존 §7 정책대로 변동성 0"), `js/16-monte-carlo-adapter.js:114`가 BOND · CASH를 riskFree로 처리한다. CMA 데이터셋에는 채권 자산군과 숫자가 이미 있다(미국 국채 4.7% / σ 6.5% 등).

변경 시 필요한 것(구현하지 않음):

| 항목 | 내용 |
| --- | --- |
| 매핑 | BOND → CMA 자산군. 단일로 묶을지 국채 · IG · HY · 해외로 나눌지 **[PM]** |
| 국내 일반채권 | CMA(AllianzGI)에 한국 채권 자산군이 있는지 확인 후 결정. 없으면 **연결하지 않는다**(임의 대체 금지) **[PM]** |
| 직접채권 vs 채권ETF | 같은 자산군으로 볼지 분리할지 **[PM]** |
| 외화채권 FX | C-2(MC 환율 모델) 결정에 종속 |
| 헤지비용 | 자료 없음 → 0으로 두지 않는다(§44 6-3) |
| 상관 | CMA 상관행렬 사용 |
| 영향 | σ 0 → 5~11%대. **P10/P50/P90이 바뀐다** → 동일 seed 전후 측정 필수 |

## 10. 외화채권 **[DESIGN]**

| 경우 | 처리 |
| --- | --- |
| 원화채권 | FX 없음 |
| 외화채권(환노출) | 평가 시 기존 환율 처리(js/09 H.10 경로와 같은 원칙) · MC는 C-2 결정에 종속 |
| 환헤지 채권 | 헤지비용 자료가 없으면 **UNRESOLVED**로 두고 추정하지 않는다 |
| 환헤지 미확인 | 미확인으로 표시 · 추정 금지 |
| FX 데이터 없음 | 원화 환산 계산을 하지 않고 사유를 표시 |

**현재 위험 명시**: MC에 환율 모델이 없어 외화자산이 사실상 FX=0으로 다뤄진다(C-2). 외화채권을 넣으면 이 문제가 더 드러난다 → **[PM]** C-2와 함께 결정.

## 12. 기존 정책과의 충돌 점검

### CONFLICT-1
- 기존 정책: §7 · BOND-DEF-03 — 채권 · 현금은 MC에서 σ = 0
- 새 설계: BOND-4 (나)안 = CMA 채권 σ 사용
- 충돌 내용: 동일 대상에 대한 상반된 규정
- 영향: MC 결과(P10/P50/P90) 변화
- **PM DECISION REQUIRED**: §7을 개정할지, 현행 유지할지

### CONFLICT-2
- 기존 정책: `RISK_ELIGIBLE_CATEGORIES = ['주식','ETF']` — 직접채권은 Risk 대상 밖
- 새 설계: BOND-2 (다)안 = 직접채권을 별도 모델로 편입
- 영향: 위험 카드 구성 · 포트폴리오 변동성 · 화면
- **PM DECISION REQUIRED**

### CONFLICT-3
- 기존 정책: §44 제10조 — 베타를 못 구하는 종목이 하나라도 있으면 포트폴리오 베타 null
- 새 설계: BOND-5 = 채권 제외 후 집계 + 제외 비중 표시
