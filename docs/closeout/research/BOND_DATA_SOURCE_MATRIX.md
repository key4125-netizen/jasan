## 2. 제4유형 "변경금지"가 계산에 미치는 의미

**[LICENSE REVIEW]** — 법률 판단은 하지 않는다. 공식 문구에서 확인되는 범위와, 해석이 갈리는 지점만 구분한다.

| 사용 형태 | 성격 | 판단 |
| --- | --- | --- |
| 받은 종가 · 수익률을 **그대로 화면에 표시**(출처 표기) | 원자료 표시 | 제2·제4유형 모두 문제 없음 |
| 평가금액 = 종가 × 보유수량 | 사용자 보유정보와의 결합 계산 | **[LICENSE REVIEW]** — 원자료를 바꾸는 것이 아니라 사용자 데이터와 곱하는 것이라 "변경"에 해당하지 않는다고 보는 해석이 가능하나, 확인 필요 |
| 일별 종가로 변동성 · MDD 산출 | 파생 통계 | **[LICENSE REVIEW]** |
| 파생값을 **저장소에 커밋 · 배포** | 재배포 | **금지**(P-12 원칙 + 비상업·재배포 제한) |
| MC 입력값으로 사용 | 파생 통계 | **[LICENSE REVIEW]** |

**설계 지침(권고)**: 제4유형 원천은 **사용자 브라우저에서 조회 → 화면 표시 · 즉시 계산**까지만 쓰고, **저장소 저장 · 배포 · 파이프라인 누적을 하지 않는다.** 그러면 재배포 제한과 충돌하지 않으며, 파생 계산에 대한 해석 위험만 남는다.

## 3. 자동 재검증(N-2) 적용 범위

"자동 수집 가능"과 "자동 적용(ACTIVE) 가능"은 다르다.

| Fact | 수집 | 비교 | 자동 ACTIVE | 조건 |
| --- | :-: | :-: | :-: | --- |
| 만기일 · 표면이율 · 이자유형 · 지급주기 · 통화 | O | O | **O** | 기존 값과 같으면 갱신 없음, 새로 채워지는 경우만 자동 |
| **기존 확정값의 변경**(만기 변경 · 쿠폰 변경 등) | O | O | **X → REVIEW** | 경제 조건 변경은 사용자 보유 계산에 직접 영향 |
| 발행잔액 · 채권 상태(상환 · 조기상환) | O | O | REVIEW | 상환 완료 시 사용자 보유와 충돌 가능 |
| 이자지급일 | O | O | O | 권리일정정보 |
| 시장가격 · 수익률 | O | O | **X** | 제4유형 · 저장 금지 · 표시/즉시계산만 |
| 채권지수 시계열 | **X** | — | — | 라이선스 미확보 |

**충돌 방지 원칙**: 자동 갱신은 **Official Terms 영역에만** 쓴다. User Holding 영역(매입일 · 수량 · 매입단가 · 계좌)은 **어떤 자동 경로도 건드리지 않는다.**

## 4. 보안 설계 요구 (구현 시 Security Final Gate 검증 항목)

| 항목 | 요구 | 근거 |
| --- | --- | --- |
| 공공데이터 서비스키 | **앱 번들 · 저장소에 넣지 않는다.** 사용자가 자기 키를 입력하거나(브라우저 보관), Worker가 보관한다 | 키 노출 = 남용 · 한도 소진 |
| CORS | 지수 API(apis.data.go.kr)는 **CORS 허용을 실측 확인**했다(Origin 반영 · GET/OPTIONS). **[INFER]** 채권 API도 같은 호스트라 동일할 가능성이 높으나 **구현 전 반드시 재확인** | 프록시 필요 여부가 여기서 갈린다 |
| OpenDART 키 | **브라우저에서 못 쓴다**(CORS 미지원 · 실측). 조사 · 재검증 전용 | 실측 |
| 저장 | 사용자가 입력한 채권 보유정보는 기존 자산과 같은 보호 수준(로컬 저장 · Data Guard) | 기존 정책 |
| 로그 · 오류 표시 | 키 · 개인정보가 오류 메시지에 노출되지 않게 한다 | 기존 정책 |
| 실패 처리 | fail-closed — 조회 실패 시 **추정값을 만들지 않는다** | §20 · 계획서 §0-2 |
| 내보내기 | 엑셀 · JSON 내보내기에 서비스키가 포함되지 않도록 한다 | Data Guard |

## 6. 보안 — KIS Proxy Worker 실측 결함 (B-1 · 2026-09-20)

저장소의 `cloudflare-worker-kis-proxy.js`에서 확인:

| # | 결함 | 위치 | 수정안 |
| --- | --- | --- | --- |
| 1 | `Access-Control-Allow-Origin: '*'` — 전면 개방 | CORS 헤더 정의부 | Origin 허용목록(운영 GitHub Pages · 개발 localhost:8644)만 반사 + `Vary: Origin` |
| 2 | `if (env.CLIENT_SHARED_SECRET && ...)` — **변수 미등록 시 인증 통째로 생략(fail-open)** | 요청 검증부 | fail-closed: 변수 없으면 503 |
| 3 | 요청 수 제한 없음 | — | KV 카운터 IP·일 300 / 분 30 초과 시 429 |
| 4 | 상류 오류 본문 전달 가능 | — | 상태코드만 반환 |

**[CONSTRAINT]** 공개 PWA에 포함되는 `X-App-Secret`은 본질적으로 공개값이다. 실질 방어선은 **Origin 허용목록 + 요청 제한**이며, 공유 비밀값은 보조 수단이다.
